# Pearl

Pearl is a private 12-week strength programme for women roughly 45–60 in perimenopause or
early postmenopause who know strength matters but are not training consistently. It combines
voice-paced home sessions with four camera-measured Movement Check-Ups so the user can see
where she started, what Pearl is prioritising, and whether her own Strength and Balance
results are changing.

Pearl also tracks optional Everyday Clarity alongside the programme. The live MVP stores a
five-item personal check-in plus sleep and symptom context. Clarity is observational: it never
changes training and is never presented as a diagnosis, treatment, cognitive score, or proof
that exercise caused a change.

The canonical product contract is [AGENTS.md](AGENTS.md). Significant decisions are recorded
in [docs/decisions.md](docs/decisions.md).

## Current product contract

- **Audience:** women about 45–60 in perimenopause or early postmenopause.
- **Journey:** Foundations, Build, and Progress — three four-week phases.
- **Cadence:** three planned sessions a week; two is a successful week.
- **Checkpoints:** baseline, week 4, week 8, and week 12.
- **Official physical check-up:** fixed warm-up → one-leg balance → 30-second chair stand.
- **Prescription:** Strength, Balance, or Balanced; Clarity never changes it.
- **Training:** voice-paced, tap-equivalent, no daily camera.
- **Camera:** official measurement only; camera video is never shown or stored.
- **Data:** local-first and on-device for the MVP.

The matched solo/dual “Steadiness while thinking” instrument is implemented and tested at the
logic layer but deliberately unmounted until its camera/microphone and target-user validity
gates pass. Verbal fluency is not an MVP surface.

## Setup

```bash
npm install
./scripts/download-models.sh
```

Pearl needs a development build because pose detection is a local native Expo module:

```bash
npx expo run:android
npx expo run:ios
```

## Development

```bash
npm run typecheck
npm test
npm run replay -- <recording.jsonl>
npm run replay -- <recording.jsonl> --assert <expected.json>
npm run fixtures
npm run audio
npm run verify:audio
npm run noise-floor -- recordings/
npm run noise-floor -- --synthetic
./scripts/pull-recordings.sh
```

When pose behaviour is surprising, capture a real landmark recording, reproduce it through
the headless replay harness, and add the recording plus expected result as a regression test
before changing a threshold.

## Layout

- `src/programme/` — the 12-week journey, physical prescription, exercise ladders, placement,
  session generation, progression, and local persistence.
- `src/screens/` — onboarding, Home, Plan, Progress, Settings, official check-up, results, and
  voice-session surfaces.
- `modules/expo-pose-detection/` — native CameraX/AVFoundation + MediaPipe PoseLandmarker.
- `src/pose/` — pure TypeScript parsing, filtering, reliability, subject validity, interruption
  handling, and body-unit calibration.
- `src/movementProfileV2/` — official check-up coordination and gated Clarity instruments.
- `src/checkup/` — versioned physical and observational check-up records.
- `src/reference/movementProfileV2/` — fingerprinted reference sources and assessment policy.
- `src/pearlFlow/` — Pearl-specific progress and longitudinal presentation models.
- `src/voice/` and `src/audio/` — on-device command handling and bundled voice playback.
- `src/recording/` and `src/replay/` — JSONL landmark recording and deterministic replay.
- `scripts/` — model, audio, fixture, replay, noise-floor, and audit tooling.

`android/` and `ios/` are generated by Expo prebuild and are not the source of truth.
